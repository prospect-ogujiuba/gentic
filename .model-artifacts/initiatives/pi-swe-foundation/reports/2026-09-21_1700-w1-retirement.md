# W-1 post-deletion integration retirement

Topic: pi-swe-foundation

## Scope and provenance

This report records the deliberate W-1 repair of the baseline left by commit `508da86` (`nuke pi-swe`). It is supporting rationale, not task authority or runtime verification evidence. `../workflow.json` remains authoritative.

## Retained behavior

- pi-todo remains a branch-local focus list with its existing actions, UI, replay compatibility, bounds, queue cancellation, and fail-closed behavior when a loaded SWE probe fails.
- Cross-extension lifecycle coordination remains optional and now uses `src/lifecycle-coordination.ts`; pi-todo no longer imports SWE storage or scans workflow files.
- Historical initiative JSON and migration evidence remain unchanged.
- Historical migration/cutover fixtures remain available for explicit future compatibility analysis; they are not active runtime tests or authority.

The `skills/swe-orchestration/` skill is also retired. Its instructions required the deleted autonomous parent/child engine and stale `/swe work ...` surface. Keeping it discoverable would direct Pi to recreate or invoke forbidden behavior.

Generic demo, inventory, and completion tests that referenced the former extension are updated as the new minimal Pi surface appears; they must not assert the deleted `/swe work`, runtime-selector, or orchestration behavior.

## Regression boundary

Before the repair, the new pi-todo package-boundary regression failed with `ERR_MODULE_NOT_FOUND` for `extensions/pi-swe/src/store.ts`. After replacing the import with shared optional coordination, focused pi-todo tests and repository typecheck pass. Final W-1/full baseline results are recorded in the initiative only after commands are actually run.
