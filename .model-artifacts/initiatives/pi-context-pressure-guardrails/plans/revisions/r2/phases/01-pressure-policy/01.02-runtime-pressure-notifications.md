## Goal and observable behavior

Existing usage-bearing lifecycle hooks feed exact samples to the pressure reducer. Downward transitions notify once using `warning` or `error` severity and concise remaining-percentage/operator guidance. Repeated samples, compaction recovery, resets, and shutdown do not emit stale or duplicate alerts.

## Scope

- Integrate normalized config and pressure state in `extensions/pi-context/src/app/session-state.ts` and `src/pi/register.ts` (or a narrowly extracted app module if needed).
- Evaluate only on hooks already reading `ctx.getContextUsage()`.
- Inject time and fake UI boundaries for tests.
- Add integration coverage in `test/pi-context-session-state.test.ts` and a focused runtime test if separation improves clarity.

## Non-goals

No filesystem scan per hook; no timer; no automatic compaction, prompt dispatch, model switch, stop, or persisted pressure history.

## Dependencies

P01-C01 complete with current verification/review evidence.

## Specialist decisions incorporated

Transition-only plain-language notifications; no color-only semantics; O(1) state; bounded diagnostics; numeric-only data; cleanup/disposal idempotency; one corrective TDD retry.

## Acceptance criteria

- AC-05 and AC-06 from spec r1.
- Unknown/estimated samples are silent.
- Warning and critical notification types are distinguishable and include no content/path data.
- State resets on a new session/shutdown and reconciles after compaction without a false downward transition.

## TDD/verification

Red order: warning transition; critical transition; repeated/oscillating samples; recovery/rearm; unavailable sample; compaction; reset/shutdown. Run focused integration tests, all existing pi-context runtime/session tests, and `npm run typecheck`.

## Rollback

Remove runtime pressure wiring and retain existing usage collection unchanged.
