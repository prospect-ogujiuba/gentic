## Goal and observable behavior

Given an exact measured context usage sample and normalized policy, classify `normal`, `warning`, or `critical`; emit a transition decision once; rearm only after recovery beyond hysteresis. Missing or estimated-only data never requests notification. Configuration deterministically merges project, global, and defaults.

## Scope

- Add pure types/evaluator/reducer under `extensions/pi-context/src/domain/`.
- Add `extensions/pi-context/src/config/index.ts` and `extensions/pi-context/pi-context.schema.json` using project `.pi/pi-context.json`, global `~/.pi/agent/pi-context.json`, and field-level precedence.
- Export the additive API through existing layer indexes.
- Add focused tests, expected in `test/pi-context-pressure.test.ts` and `test/pi-context-config.test.ts`.

## Non-goals

No Pi UI calls, report/HUD rendering, automatic action, persistence, history scan, or background timer.

## Dependencies and entry inputs

None. Existing `PiContextUsageSnapshot` and package config/resource conventions are available.

## Specialist decisions incorporated

Constant-size state and O(1) ordered comparisons; injected time; exact-measurement gate; boundary-first TDD; safe version/threshold validation; bounded diagnostics; no raw content.

## Acceptance criteria

- AC-01, AC-02, AC-03, AC-04 from spec r1.
- Defaults are warning 25%, critical 10%, hysteresis 5 percentage points.
- Invariants require `0 < critical < warning < 100` and hysteresis cannot invert recovery ordering.

## TDD/verification

Red order: classification boundaries; unavailable samples; duplicate suppression; recovery/rearm; config precedence and malformed/future config. Then run new focused tests, existing domain/session-state tests, and `npm run typecheck`.

## Rollback/migration

Ephemeral state only. Remove new modules/schema/exports; no data conversion. Unknown config versions fall back and diagnose.
