## Goal and observable behavior

`/pi-context` summary, explicit markdown/JSON artifacts, and `createPiContextHudSnapshot()` expose the same current pressure level and remaining percentage. Existing fields remain intact. Documentation explains configuration, transitions, operator response, privacy, and advisory-only limits.

## Scope

- Add additive pressure data in `extensions/pi-context/src/app/report.ts`, `src/app/hud-adapter.ts`, and associated types/exports.
- Update `extensions/pi-context/README.md` and `extensions/pi-swe/docs/e2e-scenarios.md` only if runner qualification requires a cross-reference; otherwise add a focused pi-context scenario in its README/tests.
- Extend `test/pi-context-report.test.ts` and `test/pi-context-hud-adapter.test.ts`.
- Run full qualification.

## Non-goals

No `pi-hud` rendering redesign, no new command namespace, and no automatic response to pressure.

## Dependencies

P01-C02 complete with current verification/review evidence.

## Specialist decisions incorporated

Additive compatibility; plain labels and severity independent of color; numeric-only privacy; report/HUD derive from one maintained pressure snapshot; characterize existing outputs before edits.

## Acceptance criteria

- AC-07, AC-08, AC-09 from spec r1.
- JSON/HUD contain no raw prompt, tool result, argument, credential, or source path fields.
- Existing command aliases and report sections remain valid.
