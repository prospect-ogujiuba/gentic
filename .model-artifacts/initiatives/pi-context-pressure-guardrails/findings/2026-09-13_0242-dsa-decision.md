## Problem summary

Classify each measured usage sample and suppress repeated notifications while preserving deterministic recovery behavior.

## Current implementation

`pi-context` stores a bounded array of usage snapshots and computes remaining context for reports, but has no pressure level or transition memory.

## Workload and constraints

One sample per lifecycle observation, a single active session, constant-size policy state, no range queries, no persistence, and latency negligible relative to the hook.

## Recommendation

Use a constant-size state record containing current level, last-notified level/time, and rearm flags. Evaluate each exact sample with ordered numeric comparisons. Validate configuration once and pass an immutable normalized policy to the evaluator. Do not scan usage history.

## Rejected alternatives

- A queue/time-series: unnecessary because decisions depend only on current sample and prior state.
- Debounce timers: add lifecycle/disposal complexity; transition state plus monotonic timestamps is sufficient.
- Predictive smoothing: speculative and could hide real threshold crossings.

## Complexity and memory

O(1) time and O(1) memory per observation. Existing bounded snapshots remain unchanged.

## Migration advice

State is ephemeral. Unknown future config schema versions fail safely to defaults. Rollback removes the additive record without conversion.

## Validation plan

Table-driven boundary, hysteresis, oscillation, recovery, cooldown, unavailable-usage, and reset tests. Inject time into the pure evaluator.

## Confidence

High; requirements are a small deterministic finite-state policy with no evidenced need for specialized structures.
