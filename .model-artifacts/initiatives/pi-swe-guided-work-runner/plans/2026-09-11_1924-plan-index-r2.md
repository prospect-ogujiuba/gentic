## Architecture and sequencing

1. The pure runner reducer consumes versioned runner state, a fresh `inspectCanonicalInitiative`/`recommendGateAwareOrchestration` result, and a structured checkpoint or operator event.
2. It reuses existing lifecycle transition and retry evaluation, returning a typed action: none, dispatch-stage, complete-contract, pause, stop, or blocked-handoff.
3. Persistence atomically records the next pending dispatch before any message is sent.
4. The Pi adapter queues one fixed-template `/skill:swe-*` user message with prompt expansion only while idle.
5. The skill turn must call the structured checkpoint tool. The checkpoint is accepted only for the current run/dispatch/canonical identity.
6. `agent_settled` may evaluate continuation only after a valid checkpoint. Duplicate settled events and checkpoints are idempotent.
7. Verification and review reports remain canonical evidence. Contract disposition calls the existing journaled completion boundary; the runner adds no mutation shortcut.
8. Contract target stops after disposition. Initiative target selects the next dependency-ready child or routes to finalization only after reconciliation gates.
