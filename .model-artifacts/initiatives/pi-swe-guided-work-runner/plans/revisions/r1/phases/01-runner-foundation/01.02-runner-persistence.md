# P01-C02: Versioned runner persistence and recovery

- Kind: executable subphase
- ID: `P01-C02`
- Parent: `P01`
- Plan revision: 1
- Status: pending
- Depends on: `P01-C01`
- Topic: `pi-swe-guided-work-runner`
- Active spec: r1

## Goal and observable behavior

Persist one bounded runner lease and dispatch checkpoint per topic atomically so restart/resume reconstructs the next safe action without duplicate dispatch.

## Scope

- Add a versioned runner-state envelope under `.model-artifacts/system/logs/pi-swe/<topic>/`.
- Validate repository-relative paths, topic identity, size, symlink boundaries, owner/dispatch tokens, and future versions.
- Provide atomic write, read, pause/stop, stale-owner diagnostics, and recovery classification.
- Integrate with existing repository cursor state without making runner state canonical authority.

## Non-goals

Sending prompts, handling agent events, or modifying `manifest.json`/`contracts.json`.

## Expected files

- `extensions/pi-swe/src/app/runtime.ts` or focused adjacent persistence module.
- `extensions/pi-swe/src/app/state.ts` as needed.
- `test/pi-swe-runtime.test.ts`.

## Acceptance criteria

- AC-05 and AC-08 persistence/recovery requirements pass.
- Partial, oversized, escaped, symlinked, mismatched-topic, or future-version state fails closed.
- Atomic persistence never leaves a valid-looking half-dispatch.

## Verification

Red-first temporary-repository tests for round trip, crash windows, duplicate token, stop/pause, malformed state, and future version; then `npm run typecheck` and `npm run test:swe`.

## Rollback

Stop reading the additive runner file and leave old files inert; existing repository cursor remains compatible.
