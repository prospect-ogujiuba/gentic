# P02-C01: Command and checkpoint tool surface

- Kind: executable subphase

## Goal and observable behavior

Provide `/swe work status|start|resume|pause|stop` with conservative parsing and a model-callable structured stage-checkpoint tool.

## Scope

- Parse topic, mode, until target, and bounded budget options.
- Require idle state and explicit start/resume authorization.
- Report exact active policy, stage, identity, counters, and stop reason.
- Validate checkpoint calls through the pure domain and canonical inspection layers.

## Non-goals

Actual next-turn dispatch or automatic canonical completion.

## Expected files

- `extensions/pi-swe/src/pi/commands.ts`.
- `extensions/pi-swe/src/pi/tools.ts`.
- Focused command/tool tests under `test/pi-swe*.test.ts`.

## Acceptance criteria

- AC-01, AC-02, AC-04, and operator portions of AC-09 pass.
- Invalid/ambiguous commands and checkpoint identities produce no continuation.
- Existing `/swe` commands and `swe_complete` remain unchanged.

## Verification

Red-first parser/handler/tool tests, including idle/busy, explicit autonomous selection, stop idempotence, and malformed checkpoints; then `npm run test:swe` and `npm run typecheck`.

## Rollback

Remove additive subcommand/tool registration without changing existing command semantics.
