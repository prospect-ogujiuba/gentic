## Goal and observable behavior

Define a pure, deterministic runner model that turns fresh canonical recommendations plus validated stage checkpoints into continue, pause, complete-contract, finalize, or blocked decisions.

## Scope

- Extend or wrap existing autonomous lifecycle types and retry evaluation without duplicating transition tables.
- Define run policy (`guided|autonomous`, `contract|initiative`, turn/retry/time/provider budgets), run/dispatch identity, attempt counters, and terminal reasons.
- Define structured checkpoint input/output and validation boundaries.
- Keep decision functions side-effect free and exhaustive.

## Non-goals

Pi command/event wiring, filesystem persistence, automatic plan approval, parallel contracts, or canonical completion mutation.

## Expected files

- `extensions/pi-swe/src/domain/lifecycle.ts` or one focused adjacent domain module.
- `extensions/pi-swe/src/lifecycle.ts` export surface.
- `test/pi-swe-lifecycle.test.ts` or one focused runner-domain test.

## Incorporated specialist decisions

Use a pure reducer over a single normalized runner record; reuse existing lifecycle/retry tables; use monotonic dispatch tokens and O(1) identity checks. Begin with Red table tests for clean progress, stale/duplicate identity, budget isolation, and every hard stop. Both modes retain security and human-only gates.

## Acceptance criteria

- AC-02, AC-03, AC-04, AC-06, and AC-09 domain behavior is represented explicitly.
- Existing lifecycle transitions remain authoritative.
- Duplicate/stale tokens, invalid identity, exhausted budgets, and human-only conditions fail closed.
- Decisions are deterministic for identical canonical inputs.

## Verification

Red-first table tests for clean progress, verify-fix, review-return, stop cases, stale/duplicate checkpoint, and contract/initiative stop policy; then `npm run typecheck` and `npm run test:swe`.

## Rollback

Remove the additive runner types/functions and tests; no persisted or canonical data migration.
