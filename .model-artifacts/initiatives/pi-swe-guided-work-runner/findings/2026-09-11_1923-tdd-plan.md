## Planning boundary

This finding chooses observable behavior, test level, and Red order only. It records no runtime Red evidence.

## Behavior and Red order

1. **Pure runner decision:** given a fresh canonical recommendation and valid checkpoint, the reducer returns exactly one allowed next action; invalid transition, stale identity, duplicate token, or human gate returns a terminal/paused decision. Unit table tests first.
2. **Budget isolation:** retries and turn/time/provider budgets are scoped by run ID, plan revision, contract ID, stage, and failure signature; repeated identical failure stops while a distinct contract/revision receives a fresh budget. Unit tests.
3. **Persistence recovery:** atomic state round trips, then fails closed for partial/corrupt/future/escaped/symlinked records and restart crash windows. Temporary-repository integration tests.
4. **Command authorization:** status never starts; start defaults guided; autonomous requires the exact flag; ambiguous topics, invalid budgets, and busy runtime do not dispatch. Command-handler tests with fake context.
5. **Checkpoint protocol:** only the active dispatch token and exact canonical identity can report success/failure/block; duplicate or stale calls are idempotently rejected. Tool-level integration tests.
6. **Settled continuation:** a valid checkpoint plus `agent_settled` queues one expanded `/skill:swe-*` message; duplicate settled events queue none. Fake ExtensionAPI/event tests.
7. **Loop routing:** implement→verify→review→completion; verify failure→implement within budget; review in-scope changes→implement; review material drift→paused plan; contract target stops; initiative target advances to the next ready contract. Scenario table tests.
8. **Guarded completion:** passing verification and approving review use existing completion; stale evidence, claim conflict, or journal recovery issue stops without a next prompt. Integration tests using canonical fixture.
9. **Operator interruption/restart:** pause/stop wins before queued continuation; resume continues an undispatched validated stage and does not repeat an already sent token. Event/persistence integration tests.
10. **Compatibility/documentation:** all current `/swe` tests remain green and manual fresh-session E2E examples match parser behavior.

## Test architecture

- Keep the domain reducer pure and exhaustively table-tested.
- Inject clock, ID/token generation, filesystem boundary, canonical inspector, completion function, and Pi message dispatcher into the controller.
- Use fake `ExtensionAPI` and `ExtensionContext`; do not require a live model for CI.
- Use the existing canonical plan fixture pattern and add only minimal runner artifacts.
- Keep live-provider qualification optional and separately authorized.

## Risk-scaled verification

Final qualification runs `npm run test:swe`, `npm run typecheck`, `npm run check:resources`, and `npm run check:model-artifacts` plus manual fresh-session start/resume/pause/stop.
