# Pi primitives second-pass review

The independent second pass reproduced and fixed additional issues missed by the first review:

- README anatomy claimed `simple` mode and `pi`/`resources` layers while the repository anatomy checker infers `runtime` with no `src` layers.
- Arbitrary thrown values with throwing `toString()` escaped the registration catch and prevented later primitives from registering.
- Registration diagnostics were not bounded or normalized for UI status warnings.
- Trigger definition counts and lengths were unbounded, and nonblank regexes such as `^` could still match empty input and make conditional policies always-on.
- User configuration had no file-size bound, accepted blank/duplicate disabled names, and silently ignored unknown disabled primitive names.
- The primitive scaffold generated an unused `triggers.json`, bypassed shared bounded helpers, wrote `supporting-file.md` instead of `injection.md`, emitted an invalid `**/name/**` JavaScript regex, and did not tell operators to update `EXPLICIT_PRIMITIVES`.
- The primitive catalog template and plugin guide retained directory-loading language inconsistent with explicit registration.

Regression coverage now includes hostile thrown values, 512-character diagnostics, 16 KiB config boundaries, disabled-name validation, unknown-name diagnostics, 64-entry/512-character trigger boundaries, empty-match regex rejection, inferred anatomy, and generated scaffold behavior.

The final static sweep confirms registry/resource parity, valid bounded policies and triggers, no resource symlinks, no dynamic discovery/cache-busting mechanism, accurate anatomy, bounded-helper scaffold output, compilable generated regexes, and a clean diff.
