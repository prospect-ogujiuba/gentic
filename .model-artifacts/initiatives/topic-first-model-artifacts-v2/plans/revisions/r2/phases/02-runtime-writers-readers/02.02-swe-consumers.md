# P02-C02 — Switch pi-swe and Remaining Gentic Consumers

- Kind: subphase
- Status: planned
- Spec: `.model-artifacts/initiatives/topic-first-model-artifacts-v2/specs/2026-09-01_2008-initiative-spec-r1.md`
- Plan: `.model-artifacts/initiatives/topic-first-model-artifacts-v2/plans/2026-09-01_2008-plan-index-r2.md`

## Goal and observable behavior

Canonical pi-swe authority, completion records, reviews, lifecycle artifacts, context/runtime ledgers, and Gentic-owned scripts use v2 paths; v1-only authority is inspection-only and mixed authority blocks deterministically.

## Scope and non-goals

- Advance pi-swe manifest parsing/writing to schema v2 and v2 path validation.
- Update manifest discovery, todo-link validation, contract indexes, completion transactions, orchestration, reports/logs, capabilities, skills, README, e2e scenarios, pi-context, runtime lifecycle tests, package resources, update/release scripts, and all hard-coded Gentic-owned paths.
- Retain exact revision/hash/approval semantics.
- Do not change contract graph, readiness, completion, or review policy except path/layout diagnostics.

## Dependencies and entry inputs

Depends on `P01-C01`. Inputs: complete repository path-reference inventory and v2 conformance fixtures.

## Expected files/outputs

Affected files in `extensions/pi-swe/`, `extensions/pi-context/`, root `src/`, `scripts/`, `README.md`, `CONTRIBUTING.md`, `docs/`, and corresponding tests.

## Specialist decisions incorporated

- TDD: characterize schema-v1 lifecycle semantics, then prove schema-v2, v1-read-only, and mixed-blocked behaviors separately.
- Security/compatibility: use closed schema-v2 parsing and exact topic/path/hash validation; schema v1 never enters writes/execution.
- Migration/operations: detect legacy active claims and migration-in-progress state; return actionable diagnostics instead of selecting authority.
- Repository inventory: include pi-context, lifecycle/runtime ledgers, root scripts/resources/docs, skills, examples, and all hard-coded tests.

## Acceptance criteria

- Schema-v2 manifest accepts only topic-matching initiative paths and system paths where explicitly allowed.
- Discovery resolves exactly one authority: v2 preferred only when v1 is absent; a dual presence blocks rather than selects.
- v1 manifests can be inspected and produce migration guidance but cannot enter execution or receive writes.
- Every previously hard-coded Gentic-owned kind-first runtime path is either migrated, explicitly legacy-read-only, or classified as a test fixture.
- `docs/plans/` is described only as curated human-facing documentation.

## Verification

Behavior-first pi-swe unit/integration tests across planning, lifecycle, completion, runtime, state, capabilities, and orchestration; context/runtime tests; package resource checks; focused script checks.

## Rollback/migration constraints

Readers retain bounded v1 compatibility through the migration window. Removal of v1 read support is a later separately approved cleanup.
