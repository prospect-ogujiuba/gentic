# P02-C01 — Switch pi-primitives and pi-todo

- Kind: subphase
- Status: planned
- Spec: `.model-artifacts/initiatives/topic-first-model-artifacts-v2/specs/2026-09-01_2008-initiative-spec-r1.md`
- Plan: `.model-artifacts/initiatives/topic-first-model-artifacts-v2/plans/2026-09-01_2008-plan-index-r2.md`

## Goal and observable behavior

Injected instructions and todo-generated evidence use `.model-artifacts/initiatives/<topic>/<kind>/...`; invalid, legacy-write, wrong-namespace, and mixed-topic requests fail with actionable repair.

## Scope and non-goals

- Update model-artifact injection/triggers and pi-todo constants, topic derivation, generation, evidence validation, repairs, README, and public action descriptions.
- System artifacts are not generated through initiative todo actions unless an explicit system API is designed; do not infer system placement from todo titles.
- Do not change todo scheduling, evidence semantics, or split policy.

## Dependencies and entry inputs

Depends on `P01-C01`. Inputs include v2 conformance fixtures and current `artifactTopic`, `artifactPath`, `validateGeneratedArtifact`, action schema, README, and injected developer convention.

## Expected files/outputs

`extensions/pi-primitives/primitives/model-artifacts/*`, `extensions/pi-todo/src/app/service.ts`, `extensions/pi-todo/src/pi/actions.ts`, `extensions/pi-todo/index.ts`, `extensions/pi-todo/README.md`, and focused tests.

## Specialist decisions incorporated

- TDD: implement the generation table first, then invalid/v1/mixed cases one Red at a time with actual runtime evidence.
- Security: reject absolute/traversal/backslash/control/symlink escapes and revalidate evidence paths against the project root.
- Compatibility: historical v1 evidence is readable but cannot authorize new files; local adapter behavior must pass shared conformance fixtures.

## Acceptance criteria

- All six initiative kinds generate normalized v2 paths with unchanged filename format.
- Evidence validation requires `initiatives/<topic>/<kind>/...`, checks kind/topic/name, rejects traversal and symlinks, and returns a migration-required repair for v1-only topics.
- Existing v1 evidence remains readable as historical evidence but cannot authorize a new write.
- Mixed v1/v2 topic authority blocks generation.

## Verification

TDD at unit/integration level: generation table, invalid table, v1 repair, mixed conflict, file format, evidence attachment, `npm run test:todo`, and primitive/resource tests.

## Rollback/migration constraints

Reverting this contract alone is unsafe after other v2 writers land; release only in the atomic change set.
