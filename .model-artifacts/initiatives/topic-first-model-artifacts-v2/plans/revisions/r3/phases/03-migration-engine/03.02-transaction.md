# P03-C02 — Apply, Recover, Roll Back, and Finalize Migration

- Kind: subphase
- Status: planned
- Spec: `.model-artifacts/initiatives/topic-first-model-artifacts-v2/specs/2026-09-01_2008-initiative-spec-r1.md`
- Plan: `.model-artifacts/initiatives/topic-first-model-artifacts-v2/plans/2026-09-01_2008-plan-index-r3.md`

## Goal and observable behavior

A reviewed plan applies exactly once under an exclusive claim, publishes internally consistent v2 authority, recovers after interruption, and can restore exact v1 bytes until explicit finalization.

## Scope and non-goals

- Extend transaction plan loading, preflight, staging, journal states, publication, recovery, rollback, and add explicit finalize.
- Rewrite only planner-enumerated exact references and structured fields; refresh hashes in dependency order.
- Retain bounded rollback payloads under system migration logs.
- Do not auto-apply, overwrite changed destinations, or delete rollback payloads implicitly.

## Dependencies and entry inputs

Depends on `P03-C01`. Entry requires zero plan blockers, exact plan fingerprint, unchanged sources/references, free destinations, size budget, and exclusive claim.

## Expected files/outputs

`extensions/pi-artifacts/src/app/transaction.ts`, service/command glue, types, README, transaction/recovery tests, system ledger/report/rollback bundle formats.

## Specialist decisions incorporated

- DSA: disk-backed staged/original payloads plus an append-only named-state journal; transformed graph hashes follow topological order.
- TDD: add one failure-injection Red per journal boundary and prove idempotent recovery before broad integration.
- Security: preflight and publish revalidate fingerprints/realpaths; exclusive creation; no overwrite; rollback refuses modified v2 bytes.
- Migration/operations: stable v2 claim location, explicit recovery, retained rollback bundle, and separate irreversible finalize action.
- Performance: streaming hash/copy where practical and budget checks before allocation/copy.

## Acceptance criteria

- Preflight is mutation-free and verifies all recorded fingerprints, paths, destinations, claim state, and rollback capacity.
- Staged transformed bytes are fully validated as a v2 graph before publication.
- Journal state transitions make each apply/recovery step idempotent; interruption tests cover every publication boundary.
- Rollback restores byte-identical v1 files only when current v2 bytes match ledger fingerprints; otherwise it blocks.
- Finalize removes rollback payloads only after explicit request and leaves a durable finalized ledger/report.
- No intermediate state is interpreted as two valid authorities by pi-swe.

## Verification

Integration tests inject failures at preflight, stage, publish, ledger, recovery, rollback, and finalize boundaries; compare full tree fingerprints before/after; run pi-artifacts and affected pi-swe integration tests.

## Rollback/migration constraints

The migration command's rollback is the rollback mechanism. Code rollback after repositories migrate must retain v2 readers or first restore repositories with their transaction bundles.
