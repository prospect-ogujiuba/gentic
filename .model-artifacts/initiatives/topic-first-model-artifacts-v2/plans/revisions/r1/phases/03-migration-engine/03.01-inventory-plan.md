# P03-C01 — Plan v1→v2 Relocation

- Kind: subphase
- Status: draft
- Spec: `.model-artifacts/initiatives/topic-first-model-artifacts-v2/specs/2026-09-01_2008-initiative-spec-r1.md`
- Plan: `.model-artifacts/initiatives/topic-first-model-artifacts-v2/plans/2026-09-01_2008-plan-index-r1.md`

## Goal and observable behavior

`/artifacts audit` and `plan` classify v1/v2 authority and produce a deterministic, bounded, reviewable complete relocation/rewrite plan without mutating candidates.

## Scope and non-goals

- Extend inventory/classification for complete kind-first initiative trees, v2 initiatives, system artifacts, mixed topics, references, manifests, plan indexes, contract indexes, and transaction records.
- Emit plan/Markdown report beneath `.model-artifacts/system/logs/model-artifact-migration/`.
- Build exact old→new paths and exact reference rewrite sets; plan manifest schema/path/hash updates.
- Do not apply moves or guess ambiguous topic ownership.

## Dependencies and entry inputs

Depends on `P02-C01` and `P02-C02`. Inputs: v2 contract, both manifest schemas, current inventory bounds/config, reference trie, normalization and fingerprint utilities.

## Expected files/outputs

`extensions/pi-artifacts/src/domain/{inventory,normalize,plan,types}.ts`, app service/command surfaces, README, config behavior where needed, and exhaustive planner tests.

## Specialist decisions incorporated

Pending DSA, migration, security, performance, operations, and compatibility findings.

## Acceptance criteria

- Deterministic sorted relocation table groups a topic's six kinds under one v2 root and system records under `system`.
- Mixed authority, ambiguous ownership, unsupported files, collisions, stale/unsafe references, symlinks, and bounds are blockers.
- Protected canonical v1 files become migratable only as a complete authority set, never as isolated legacy Markdown.
- Plan records source fingerprints, reference sites, transformed destinations, expected post-transform hashes, bounds, and rollback size estimate.
- Re-running plan on identical bytes produces an identical semantic fingerprint.

## Verification

Unit/property-style fixture tables for classification, normalization, ordering, collision/conflict/reference closure, bounds, schema transforms, and stable fingerprinting; command integration dry-run test.

## Rollback/migration constraints

Planning is read-only except its system log/report. An active migration transaction blocks new planning that could include its own records.
