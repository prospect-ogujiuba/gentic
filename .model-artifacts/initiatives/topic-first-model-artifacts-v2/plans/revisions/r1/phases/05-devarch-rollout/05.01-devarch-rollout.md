# P05-C01 — Gated DevArch Migration Handoff

- Kind: subphase
- Status: draft
- Spec: `.model-artifacts/initiatives/topic-first-model-artifacts-v2/specs/2026-09-01_2008-initiative-spec-r1.md`
- Plan: `.model-artifacts/initiatives/topic-first-model-artifacts-v2/plans/2026-09-01_2008-plan-index-r1.md`

## Goal and observable behavior

DevArch is audited and migrated exactly once only after consuming the verified Gentic release, with repository-specific approval, rollback retention, and post-migration verification.

## Scope and non-goals

- In DevArch, record installed Gentic version, clean worktree/snapshot, artifact bounds, external path consumers, and backups.
- Run audit and plan; review mappings, blockers, reference rewrites, storage estimate, and verification commands; obtain explicit repository-owner approval.
- Apply once, audit, verify DevArch, and retain rollback until owner finalizes.
- Do not change DevArch architecture, canonical plans, or content beyond mechanical migration/rewrite.

## Dependencies and entry inputs

Depends on `P04-C01`, a released/installed Gentic version containing v2, a zero-blocker DevArch plan, adequate rollback storage, and explicit approval of that exact plan fingerprint.

## Expected files/outputs

DevArch system migration plan/report, approval record, ledger/rollback bundle, post-apply audit, repository-specific verification report, and finalization decision.

## Specialist decisions incorporated

Pending findings plus repository-specific migration review at execution time.

## Acceptance criteria

- No DevArch move occurs before all entry gates pass.
- Exact saved plan is applied once; no manual parallel rearrangement occurs.
- Post-apply audit shows only v2 canonical authority and no mixed topic.
- DevArch's agreed tests/build/docs checks pass.
- Rollback remains possible until an explicit owner finalize decision.

## Verification

DevArch-specific commands are discovered and recorded before approval; run audit dry-run, plan fingerprint check, post-apply audit, path-reference scan, and the agreed test/build suite.

## Rollback/migration constraints

Rollback uses only the retained transaction ledger/bundle and blocks on modified v2 bytes. Any content/design correction returns to normal DevArch planning rather than being folded into migration.
