# P01-C01 — Define v2 Path Contract and Red Conformance Suite

- Kind: subphase
- Status: draft
- Spec: `.model-artifacts/initiatives/topic-first-model-artifacts-v2/specs/2026-09-01_2008-initiative-spec-r1.md`

## Goal and observable behavior

Encode layout-v2 examples and invalid cases once as declarative conformance fixtures. Before production changes, focused tests fail because current adapters emit kind-first paths.

## Scope and non-goals

- Add test-owned fixtures for initiative roots, system roots, canonical exceptions, v1 recognition, mixed-layout conflicts, unsafe paths, and filename rules.
- Define the release compatibility contract and source-of-truth rule.
- Do not switch production writers or build migration behavior.
- Preserve standalone extension packaging; do not add cross-extension runtime imports.

## Dependencies and entry inputs

None. Inputs: spec r1, current injected convention, pi-todo path adapter, pi-swe manifest parser/discovery, pi-artifacts classifier, pi-context ledgers, and package resource checks.

## Expected files/outputs

- `extensions/pi-primitives/primitives/model-artifacts/` declarative convention/resource updates.
- Shared test fixtures under `test/fixtures/` or a comparably package-neutral test path.
- Focused failing tests in `test/pi-primitives.test.ts`, `test/pi-todo.test.ts`, `test/pi-swe-*.test.ts`, `test/pi-artifacts.test.ts`, and affected context/resource tests.

## Specialist decisions incorporated

Pending DSA/TDD/security/migration/compatibility review.

## Acceptance criteria

- Fixtures distinguish initiative and system namespaces, v1/v2, canonical exceptions, and invalid/mixed paths.
- Every active extension adapter is represented by at least one conformance test.
- Red failures demonstrate missing v2 behavior, not malformed fixtures.
- No production writer changes occur in this contract.

## Verification

Run the focused fixture/resource and adapter tests; record expected Red names and failure summaries. Do not claim Red until tests actually run during implementation.

## Rollback/migration constraints

Fixtures are additive and reversible. They must not instruct users to migrate before the transaction contracts are complete.
