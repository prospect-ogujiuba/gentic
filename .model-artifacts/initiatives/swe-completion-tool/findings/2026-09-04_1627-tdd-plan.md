## Observable behaviors and test levels

1. **Confirmation gate** — unit/tool integration: `confirm: false` rejects before resolver I/O and no manifest/index/journal bytes change.
2. **Selection** — resolver integration: explicit topic/contract succeeds; omitted fields succeed only with exactly one active canonical initiative and one manifest active contract; zero/multiple candidates reject deterministically.
3. **Current contract identity** — resolver integration: active plan/index/path/hash are derived and the current contract bytes must match the indexed hash.
4. **Unique approval** — filesystem integration: zero matching current approving review envelopes rejects; two matching envelopes reject as ambiguous regardless of timestamp or referenced verification validity.
5. **Exact evidence chain** — filesystem integration: the unique review file hash is calculated; its bound verification path/hash is followed; the verification bytes and envelope must be pass/gaps-none for the same current identity.
6. **Safety bounds** — integration: traversal, absolute/backslash, symlink, non-file, direct-child violation, per-file oversize, report-count overflow, and aggregate-byte overflow reject without writes.
7. **Guarded mutation delegation** — integration: valid request completes/advances or clears through the existing transaction; replay is `already-complete`; contention and injected recovery behavior remain unchanged.
8. **Registration/compatibility** — extension integration: `swe_complete` schema is present, `next` uses a Google-compatible enum/default, existing `/swe complete` still works, docs/inventory describe both surfaces.
