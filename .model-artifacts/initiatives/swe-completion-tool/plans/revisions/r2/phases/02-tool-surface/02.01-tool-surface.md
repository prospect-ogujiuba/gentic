## Goal

Register `swe_complete` as a concise LLM-callable Pi tool that gates on explicit confirmation, derives the full request through P01, and delegates the only mutation to `completeCanonicalContract` unchanged.

## Observable behavior

```json
{
  "topic": "swe-completion-tool",
  "contractId": "P01-C01",
  "confirm": true,
  "next": "advance"
}
```

`topic`, `contractId`, and `next` are optional; `confirm` is required. `next` defaults to `advance`. With valid current evidence the tool returns the same completion disposition/next state as the low-level transaction. `confirm !== true` or resolver failure returns a compact rejection without scanning/mutation. `/swe complete` remains unchanged.

## Scope and non-goals

### Scope

- Add `extensions/pi-swe/src/pi/tools.ts` with tool schema, registration, confirmation gate, resolver call, transaction delegation, and bounded text/structured details.
- Wire registration from `extensions/pi-swe/index.ts` without changing command registration.
- Use Pi `Type` and Google-compatible `StringEnum(["clear", "advance"])` (or exact installed equivalent).
- Update affected extension test doubles, completion/tool integration tests, README orientation/commands documentation, and `docs/e2e-scenarios.md`.
- Regenerate checked catalog/inventory artifacts only when repository checks identify them as generated outputs.

### Non-goals

- No UI confirmation prompt, command alias/removal, autonomous verify/review, report-body output, legacy namespace, or peer-extension dependency.

## Specialist decisions incorporated

- **TDD:** first runtime Red is a registration/schema test proving `swe_complete` is absent; execute confirmation, valid delegation, rejection, clear, advance, and replay behaviors incrementally.
- **Security:** `confirm` must be exactly true and is checked before resolver I/O; tool never accepts caller-supplied hashes/paths/revisions.
- **Operations:** pass transaction statuses through semantically; contention remains conflict, recovery artifacts remain visible, no lock auto-reaping or outer mutation queue.
- **Compatibility:** additive tool; command and direct API unchanged; update explicit no-tool documentation/tests; Google-compatible enum; concise content plus structured details.

## Acceptance criteria

1. Pi registers exactly one `swe_complete` tool with optional string `topic`, optional string `contractId`, required boolean `confirm`, and optional `next` enum `clear|advance`.
2. `confirm !== true` returns `rejected` before resolver/evidence I/O and no write/journal is created.
3. `next` defaults to `advance`; `clear` is passed unchanged into the derived low-level request.
4. Resolver rejection and transaction `rejected|conflict|blocked-recovery|completed|already-complete` statuses remain distinguishable with bounded text and structured details; report bodies are never returned.
5. A valid execute call invokes exactly one unchanged guarded transaction; concurrent calls still produce one winner under the existing claim.
6. `/swe complete`, direct API, schema normalization, completion records, recovery, and fault behavior pass existing regression tests without syntax/semantic changes.
7. README/e2e docs describe the concise tool, optional inference constraints, fail-closed evidence selection, retained long command, and no autonomous lifecycle behavior.
8. `npm run test:swe`, `npm run typecheck`, `npm run check`, and `npm test` pass.
