## Goal

Add a non-mutating resolver that derives the existing full completion request from one exact active canonical contract and one exact approving review.

## Observable behavior

Explicit or uniquely inferable topic/contract inputs produce one fully derived request; absent, stale, unsafe, or ambiguous canonical/evidence state rejects before mutation.

## Scope and non-goals

Scope: resolver behavior, strict envelope reuse, bounded report discovery, file hashing, and resolver tests. Non-goals: changing the transaction, envelope schema, or low-level command.

## Dependencies and entry inputs

- Dependencies: none.
- Entry inputs: current completion/inspection implementation, spec r1, and required specialist findings before final approval.

## Expected files/outputs

- `extensions/pi-swe/src/completion.ts` and/or one focused non-mutating completion-resolution module.
- `test/pi-swe-completion.test.ts` resolver fixtures and rejection/success tests.

## Specialist decisions incorporated

Pending TDD and cross-cutting safety/compatibility review.

## Acceptance criteria

- Resolve explicit or uniquely inferable active identity.
- Recompute contract/review/verification hashes and validate exact envelope bindings.
- Reject zero/multiple matching reviews, unsafe paths, symlinks, bounds violations, and stale evidence without writes.
- Return the unchanged `CompleteCanonicalContractRequest` shape only after all derivation checks pass.

## Verification

Behavior-first unit/integration fixtures covering selection, report candidates, envelope identity, path safety, bounds, and exact request derivation; focused `npm run test:swe`.

## Rollback / migration constraints

No persisted migration. Keep `completeCanonicalContract` and its strict validation unchanged; resolver removal must restore prior behavior without state conversion.
