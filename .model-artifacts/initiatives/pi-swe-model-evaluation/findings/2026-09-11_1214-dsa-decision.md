## Problem summary

Preserve authoritative event order, correlate tool calls/results, compare canonical mutations, and aggregate bounded trials deterministically without introducing a second workflow database.

## Current implementation

No model-level evaluator exists. Pi Marathon demonstrates SQLite-backed durable orchestration, while Pi-SWE tests use in-memory fixture builders. Neither directly represents a bounded independent benchmark run.

## Workload / constraints

Dominant operations are append events, one-pass reduction, keyed correlation by trial/tool/contract, stable serialization, and aggregate counting. Expected initial scale is tens of trials per model/scenario and thousands—not millions—of events per trial. Facts are inferred from Pi event/session formats and planned qualification size; no measured performance problem exists.

## Recommendation

Use versioned plain TypeScript records, append-only JSONL traces as source evidence, one JSON score per trial, and deterministic aggregate JSON. Reduce traces in one pass using `Map`/`Set` keyed by tool-call ID and contract ID; retain completion order in an array. Compare immutable files by SHA-256 and expected mutable canonical state structurally. Sort keys/rows before serialization.

## Rejected alternatives

- SQLite: valuable for Marathon restartable scheduling, but unjustified for the initial bounded evaluator and adds schema/migration/concurrency authority.
- Parsing transcript prose: not authoritative and difficult to correlate.
- One monolithic JSON trace: weaker streaming/crash recovery and higher rewrite cost than JSONL.

## Complexity impact

Capture is O(1) append per event. Scoring is O(E + F), where E is recorded events and F is snapshot files. Aggregation is O(T + M log M) for T trials and deterministic output sorting. Hashing is linear in fixture/result bytes.

## Memory tradeoff

Maps and ordered vectors duplicate bounded identifiers and summaries; raw large payloads remain on disk. Streaming reduction avoids loading every transcript body where possible.

## Migration advice

Start every record with `schemaVersion: 1`; reject unknown versions. No existing state migration. If resumability or volume later requires SQLite, add an explicit export/import revision while keeping JSONL as audit evidence.

## Validation plan

Golden deterministic serialization tests, shuffled-input ordering tests, missing/duplicate tool-result tests, large synthetic trace measurement, and content-tree digest reproducibility tests.

## Confidence

High for correctness and initial scale; performance assumptions are inferred and should be measured before adding persistence complexity.
