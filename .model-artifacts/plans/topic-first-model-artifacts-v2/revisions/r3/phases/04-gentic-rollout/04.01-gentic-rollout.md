# P04-C01 — Integrate, Document, Release-Verify, and Migrate Gentic

- Kind: subphase
- Status: planned
- Spec: `.model-artifacts/specs/topic-first-model-artifacts-v2/2026-09-01_2008-initiative-spec-r1.md`
- Plan: `.model-artifacts/plans/topic-first-model-artifacts-v2/2026-09-01_2008-plan-index-r3.md`

## Goal and observable behavior

The complete Gentic v2 change passes focused and repository-wide checks, public documentation has one source-of-truth rule, and Gentic's own artifact history is migrated once from a saved reviewed plan.

## Scope and non-goals

- Reconcile every relevant source/test/doc reference found by repository inventory.
- Update public extension docs, root docs, release notes/process, package resources, and migration operator guide.
- Run focused suites, full suite, static resource/catalog/inventory/anatomy/command/performance checks, and release verification.
- Audit/plan/review/apply Gentic's tree, then repeat tests and audit while retaining rollback.
- Do not migrate DevArch in this contract.

## Dependencies and entry inputs

Depends on `P03-C02`. Entry requires all focused suites green, no unclassified hard-coded runtime path, and a clean scoped worktree for the migration transaction.

## Expected files/outputs

Documentation/test updates across the repository; saved Gentic migration plan, review decision, apply ledger, rollback bundle, post-migration audit/report, and verification log.

## Specialist decisions incorporated

- TDD: retain actual focused Red/Green/Refactor evidence per behavior, then broad verification before and after migration.
- Security/migration: require clean enumerated sources, exact reviewed fingerprint, storage budget, pre/post audit, and byte-safe rollback rehearsal.
- Performance: record Gentic file/byte/reference counts and audit/plan/apply duration before DevArch.
- Operations/compatibility: document v1 deprecation window, recovery/finalize consequences, and classify every remaining v1 string as fixture/compatibility intent.

## Acceptance criteria

- All AC1–AC8 evidence is present and current.
- Repository search classifies every remaining kind-first string as intentional v1 fixture/compatibility code or removes it.
- Full `npm test`, checks, and release verification pass before and after self-migration.
- Post-migration audit reports no canonical v1 initiative authority and no mixed topic.
- Rollback bundle is retained and its restore procedure is documented/tested before release.

## Verification

Focused suites; `npm test`; check scripts from `package.json`; `npm run release:verify`; migration dry run; post-apply audit; repeat full verification. Capture only summarized evidence artifacts.

## Rollback/migration constraints

If any post-migration verification fails, stop release and use the retained ledger/bundle unless the failure is understood and an approved in-scope correction is safer. Never manually rearrange protected authority.
