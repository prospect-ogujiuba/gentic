# Subphase 01.03: Specialist, approval, and readiness reducer

Created: 2026-08-30
Purpose: Prevent draft, stale, blocked, or dependency-incomplete plans from appearing executable.

## Goal and observable behavior

A pure reducer reports initiative readiness, plan-review readiness, approval validity, ready contracts, and ordered blocking reasons from manifest, contracts, graph results, specialist matrix, and available artifact links.

## Dependencies

- `01.01`
- `01.02`

## Expected files

- Add `extensions/pi-swe/src/domain/readiness.ts`.
- Extend planning tests and relevant lifecycle transition tests.

## Implementation contract

1. Define stable gate IDs/results: `spec-ready`, `plan-review-ready`, `plan-approved`, `contract-ready`, `finalize-ready`.
2. Validate all core specialist IDs; require rationale for `not-required` and finding path for consequential `complete` entries where configured.
3. Match approval to active plan revision/path and reject stale or missing review evidence.
4. Combine graph readiness with approval, dependency, entry-input, and capability facts.
5. Return all blocking reasons in deterministic severity/gate/contract order, not only the first failure.
6. Keep filesystem existence as explicit input facts; never read files or infer approval by filename.
7. Define compact trivial-plan eligibility without bypassing applicability, acceptance, verification, or approval.

## TDD boundary

Red first: a complete set of files without approval remains non-executable; matching approval plus complete dependencies yields exactly the first ready contract. Add stale revision, blocked specialist, missing rationale, multiple ready, and finalize-with-deferral cases. Test level: unit.

## Acceptance criteria

- No boolean named `hasPlan` is sufficient for approval/readiness.
- Blocking reasons name remediation and relevant artifact/contract when available.
- Finalization distinguishes approved deferrals from incomplete work.
- Reducer is independent of Pi runtime and pi-todo.

## Verification

Focused tests, `npm run test:swe`, and `npm run typecheck`.

## Handoff

Phase 02 may consume these types only after Phase 01 tests and typecheck pass.
