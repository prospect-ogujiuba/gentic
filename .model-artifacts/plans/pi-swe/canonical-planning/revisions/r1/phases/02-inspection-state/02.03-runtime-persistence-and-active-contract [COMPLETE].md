# Subphase 02.03: Runtime persistence and active-contract state

Created: 2026-08-30
Purpose: Resume canonical work safely across sessions and reject stale execution cursors.

## Goal and observable behavior

Persisted pi-swe state records active initiative and contract pointers with schema/revision identity. Reconstruction validates those pointers against canonical inspection; future/legacy versions migrate or degrade explicitly instead of activating stale work.

## Implementation contract

1. Introduce a versioned persisted active-initiative shape: topic, manifest path/schema, plan revision/path, contract ID/path, and lifecycle/gate summary sufficient for UI caching.
2. Preserve decoding of version-1 `activePlan` entries as legacy markers; never upgrade them to approved state without canonical inspection.
3. On refresh/resume, validate persisted pointers against the inspector and clear/diagnose stale revision or missing contract pointers.
4. Keep active todo as optional fallback context only when no canonical persisted marker exists.
5. Separate turn-local inspected/changed/verification facts from durable initiative cursor.
6. Specify atomic writes for repository `state.json` (temporary sibling, fsync/rename where supported); session custom-event persistence remains versioned append behavior.
7. Bound state size and diagnostics.

## TDD boundary

## Acceptance criteria

- Runtime never labels a todo marker as canonical approved plan.
- Fresh session recovers the same canonical topic/contract when artifacts are unchanged.
- State invalidation is explicit and actionable.
- Existing advisory read-before-edit/verification state remains functional.
