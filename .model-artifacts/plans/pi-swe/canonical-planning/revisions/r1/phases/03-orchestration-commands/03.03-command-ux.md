# Subphase 03.03: Status and orchestration command UX

Created: 2026-08-30
Purpose: Give developers concise, unambiguous initiative/gate/contract visibility and topic selection.

## Goal and observable behavior

`/swe status [topic]` and `/swe orchestrate <status|start|resume|handoff> [topic]` resolve the intended initiative and show canonical state. Existing `/swe config`, command name, skill surfaces, and guidance-only semantics remain.

## Dependencies

- `03.02`

## Expected files

- Update `extensions/pi-swe/src/pi/commands.ts`.
- Update runtime view-model support if needed without duplicating inspection.
- Update `test/pi-swe.test.ts` and command inventory expectations only if completions change.

## Implementation contract

1. Implement whitespace-safe argument parsing for action and optional multi-segment topic.
2. Add completions for existing subcommands/actions; do not enumerate repository topics unless bounded and safe.
3. Status fields: source mode, initiative/topic, schema, initiative state, active spec/plan revision, approval decision, specialist/gate summary, active contract, ready contracts, blockers, todo linkage, and existing turn discipline counts.
4. Orchestrate output: readiness, next skill/stage, reason, required read/write paths, and exception handoff.
5. Ambiguity/invalid/legacy states use warning notification and actionable next command; valid canonical state uses info unless blocking.
6. Preserve bounded output and avoid dumping manifests or todo content.
7. Keep old no-argument behavior useful: resolve persisted/unique initiative or report none/ambiguity.

## TDD boundary

Red first: explicit topic status renders revision/gate/contract fields. Add no-topic unique, no initiative, multiple candidates, legacy, stale, start/resume/handoff, existing config, and current status discipline fields. Test level: integration.

## Acceptance criteria

- Usage strings exactly document optional topic syntax.
- `/swe orchestrate` still performs no hidden model call, file write, or implementation.
- Existing command inventory remains one `/swe` command.
- Output is concise and stable enough for manual scenario checks.
