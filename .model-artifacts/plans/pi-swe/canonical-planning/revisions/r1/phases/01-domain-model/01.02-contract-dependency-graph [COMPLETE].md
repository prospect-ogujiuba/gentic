# Subphase 01.02: Contract dependency DAG and deterministic ready set

Created: 2026-08-30
Purpose: Make chronological phase/subphase order explicit and safely executable.

## Goal and observable behavior

Given contract metadata and completion state, validation returns a deterministic topological order and ready contract IDs; duplicate IDs, unknown dependencies, self-edges, parent mismatches, and cycles are rejected with actionable diagnostics.

## Dependencies

- `01.01` manifest/revision types.

## Expected files

- Add `extensions/pi-swe/src/domain/contract-graph.ts`.
- Extend planning/lifecycle unit tests with table fixtures.

## Implementation contract

1. Define immutable `ContractId`, phase/subphase metadata, `dependsOn`, plan revision, path, and status shapes.
2. Validate hierarchical IDs (`NN`, `NN.NN`) and require subphase parent consistency.
3. Build `Map<id,node>`, adjacency lists, and in-degree counts.
4. Use Kahn's algorithm for cycle detection/topological order in O(V+E).
5. Compute ready nodes only when incomplete, dependencies complete, and caller-provided gate predicate passes.
6. Sort zero-in-degree/ready ties by numeric hierarchical ID, falling back to stable lexical comparison only for equivalent normalized shapes.
7. Return diagnostics rather than partial executable results when graph integrity fails.

## TDD boundary

Red first: linear graph order and ready set, then branching ties, duplicate, missing dependency, self-edge, cycle, and `01.02` under wrong parent. Test level: unit.

## Acceptance criteria

- Results are independent of input array order.
- Graph functions do not mutate caller input.
- Cycle diagnostics include involved IDs when determinable.
- Empty and single-contract plans have defined results.
- Complexity remains O(V+E) aside from bounded deterministic ordering.

## Verification

Focused planning tests; `npm run test:swe`; `npm run typecheck`.

## Non-goals

No parallel worker execution or incremental graph cache.
