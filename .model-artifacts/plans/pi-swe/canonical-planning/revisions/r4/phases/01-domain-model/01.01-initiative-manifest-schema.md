# Subphase 01.01: Initiative manifest and revision schema

Created: 2026-08-30
Purpose: Define the canonical machine-readable identity and revision contract.

## Goal and observable behavior

A valid schema-v1 manifest parses into a typed canonical initiative; unsupported versions, unsafe paths, topic mismatches, invalid lifecycle states, and inconsistent active revision/approval pointers return stable diagnostics.

## Dependencies

None.

## Expected files

- Add `extensions/pi-swe/src/domain/initiative.ts`.
- Add or update a narrow extension-local export such as `extensions/pi-swe/src/initiative.ts` if public test imports require it.
- Add focused cases to `test/pi-swe-lifecycle.test.ts` or a new `test/pi-swe-planning.test.ts`.

## Implementation contract

1. Define safe multi-segment topic validation without resolving outside `.model-artifacts`.
2. Define schema-v1 discriminated unions for draft vs approved manifests, active spec/plan pointers, approval record, specialist entries, and active contract pointer.
3. Normalize and validate repository-relative linked paths using existing lifecycle path rules where reusable.
4. Require approval plan revision/path to equal the active plan; require zero blocking findings for approved state.
5. Reject forward versions explicitly and preserve bounded diagnostic codes/messages.
6. Keep parsing pure: accept unknown data, return typed success/failure, and perform no filesystem access.

## TDD boundary

Red first: parse one valid draft fixture, then reject `../`, absolute paths, mismatched initiative/topic, version 2, and stale approval revision. Test level: unit.

## Acceptance criteria

- No `as`-only trust boundary exposes unvalidated manifest data.
- Draft and approved requirements are structurally distinct.
- Existing stable artifact kinds remain accepted; todo plans are not canonical active-plan paths.
- Diagnostics identify field and reason without throwing for ordinary invalid input.

## Verification

Focused Node test for the planning/lifecycle file; then `npm run typecheck`.

## Non-goals

No JSON file read/write or content-hash implementation beyond typed fields.
