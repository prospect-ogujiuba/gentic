## Review

Journal state machine: approve. The journal stage is a closed enum: `prepared`, `contract-index-installed`, `manifest-installed`, `rollback`, `validated`, `cleanup`. Each stage states required prepared/backup artifacts, allowed target preimage/prepared hash combinations, normal transition, recovery transition, and fsync obligations. Allowed combinations explicitly include crashes between a target rename and the following stage update.

Rollback: approve. Every pre-commit recovery persists `rollback` before the first restore. `rollback` accepts either preimage/prepared target hash while requiring both verified backups, restores/verifies both preimages, and resumes deterministically after a crash between restores. Missing/corrupt required backups block recovery.

Validated cleanup: approve. Durable `validated` commits new canonical bytes. Recovery never rolls back from `validated` or `cleanup`; it verifies new target hashes/cross-state validity and idempotently removes any subset of remaining prepared/backups. Journal deletion is last. Thus a crash after validated with partial backup removal is executable without backups.

Completion-record disposition: approve. Each record key must exist and its indexed status must be exactly `complete`; pending, in-progress, blocked, absent, and mismatched records are rejected.

Next-state snapshot: approve. Creation and post-write inspection require initiative state, active ID, and exact sorted ready IDs to match the same prepared manifest/index/reducer snapshot. Later reload treats that value as immutable history, validating ID existence without incorrectly comparing it to legitimately advanced current state; repeated output separates recorded/current state.

TDD: approve. Fault injection covers every closed stage, rename-before-stage gaps, restore gaps, every cleanup subset, status cross-invariants, same-snapshot mismatches, and later advancement.
